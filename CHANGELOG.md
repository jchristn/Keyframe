# Changelog

## v0.1.0 (unreleased, alpha)

First development release. Not yet published.

### Added

- Request and response contracts for image and video analysis: `Summarize` and `Extract` functions with typed `Fields`, plus video `Scenes` and `Transcribe` functions.
- Media pipeline on ffmpeg and ffprobe: magic-byte type detection, SSRF-guarded URL download, probing, image normalization, scene detection with minimum, maximum, and count rules, keyframe extraction, and chunked audio extraction.
- Inference seam (`IInferenceClient`, `ITranscriptionClient`) with deterministic mock providers, per-endpoint concurrency limits, and per-call timeouts.
- `Keyframe` meter and activity source with metrics for analyses, stages, model calls, tokens, ffmpeg, jobs, and authentication.
- Analysis engine: prompt builder with a fenced, data-only context block shared by every prompt, `Combined` and `PerField` extraction, lenient JSON parsing with a repair loop, retries with backoff, type coercion with per-field warnings, and per-request telemetry (stage timings, every model call and attempt, token totals).
- Persistence on SQLite, MySQL, PostgreSQL, and SQL Server with versioned, idempotent migrations: request history (with a header child table), jobs, and job results. The database suites pass against all four providers.
- REST server on Watson 7 with OpenAPI and Swagger UI: image analysis, video jobs (queued, cancelable, durable, marked `Interrupted` after a restart, optional synchronous `Wait`), probe, jobs, endpoints and endpoint tests, settings read and update with masked secrets and live-versus-restart metadata, restart, and request history with gap-filled summaries.
- DocumentAtom-style authentication: named access keys plus an admin key, accepted as a bearer token or `x-api-key`, compared in constant time, with per-address rate limiting of failed attempts.
- Request capture for every call with secret headers redacted and bodies truncated, written in the background.
- Radiant telemetry host exporting the Keyframe and Watson meters and sources over OTLP and Prometheus.
- `REST_API.md` and a Postman collection under `assets/postman/`.
- MCP server on Voltaic 2.4 (Streamable HTTP, JSON-RPC, TCP, WebSocket) with nine tools that call the REST server through the C# SDK, bearer authentication, and `--install`/`--uninstall` for Claude Code, Codex, Gemini CLI, Cursor, and Mux. `MCP_API.md` documents every tool.
- MCP clients authenticate with their own Keyframe key (the same access or admin key used for REST). The MCP server checks it with `GET /v1.0/whoami` (cached 60 seconds) and makes every tool call with that key, so rights are identical over REST and MCP. `Keyframe.AccessKey` is only a fallback for the unauthenticated TCP transport. MCP tools for audio, segments, and analytics.
- SDKs for C# (`Keyframe.Sdk`, net8.0 and net10.0), JavaScript (`keyframe-sdk`), and Python (`keyframe_sdk`), each with a harness that runs against a live server.
- Docker images for the server and MCP server, a Compose stack with an OpenTelemetry collector, Prometheus, Tempo, Loki, and Grafana with six dashboards, update scripts, and a factory reset with sample media. `TELEMETRY.md` and `DOCKERHUB_README.md`.
- xUnit and NUnit runners for the shared suites and a GitHub Actions workflow covering all four database providers, three operating systems, the dashboard, and the SDK harnesses.
- React dashboard (React 19, Vite 6): analyze image and video, jobs with scene timeline and transcript, endpoints, request history, API Explorer, settings with restart, server info; dark and light themes, i18n.
- Docker Hub images `jchristn77/keyframe-server`, `jchristn77/keyframe-dashboard`, and `jchristn77/keyframe-mcp` (tag `v0.1.0`) used by `docker/compose.yaml`, and `build-*.sh`/`build-*.bat` scripts that build for linux/amd64 and linux/arm64/v8, tag the given version and `latest`, push, and pull.
- Real model providers through PolyPrompt 5.0: Ollama, Ollama Cloud, OpenAI, Azure OpenAI, OpenAI-compatible servers, Anthropic, Gemini, xAI, and Cohere for vision completions, and OpenAI, Azure OpenAI, and OpenAI-compatible servers for transcription with timed segments. JSON object output is requested natively on OpenAI, Azure OpenAI, and xAI. `GET /v1.0/endpoints` reports `SupportsImages`, `SupportsStructuredOutput`, and `SupportsTranscription`. A misconfigured endpoint (missing key or URL) fails with 502.
- Provider suite against a local OpenAI-compatible stub, and opt-in live provider tests (`KEYFRAME_TEST_OLLAMA_URL` and `KEYFRAME_TEST_OLLAMA_MODEL`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`).
- Audio analysis: `POST /v1.0/audio` queues a job (`MediaKind: "Audio"`) that transcribes audio files (mp3, wav, flac, m4a or aac, ogg or opus, webm audio) or the audio track of a video in parallel chunks, then summarizes and extracts typed fields from the transcript with the text model. Transcribe and Summarize are on by default. `AudioAnalysisResponse` adds `Transcript`. New setting `Media.MaxAudioDurationMs`. MP3 cover art is no longer mistaken for a video stream.
- Segment retrieval: `POST /v1.0/segment` cuts a video clip (mp4 or webm, re-encoded for accurate cuts), an audio clip (mp3, wav, flac, m4a, ogg), or a still frame (jpg or png) out of a source, returned as binary media with `Content-Disposition` and `x-keyframe-segment-*` headers or as JSON with base64 data. New setting `Media.MaxSegmentMs` (default 600000).
- Streaming model calls: completion calls stream through PolyPrompt, and every call reports `TimeToFirstTokenMs`, `GenerationMs`, `TokensPerSecond`, and `QueueMs` (time waiting on the endpoint's concurrency gate). `AnalysisTelemetry.QueueWaitMs` records job queue time, and responses carry the submitting `RequestId`. The mock provider reports deterministic simulated timing.
- Analytics: schema migration 2 adds `analyses` and `modelcalls` (one row per attempt) on all four databases. Every finished analysis is written in the background. Admin routes `GET /v1.0/analytics/summary` (percentiles, gap-filled minute, hour, or day buckets, by media kind, model, stage, and purpose), `GET /v1.0/analytics/analyses`, `GET /v1.0/analytics/analyses/{id}`, and deletes. Settings `Analytics.Enable` and `Analytics.RetentionDays` (default 90), pruned by maintenance.
- New metrics: `keyframe.model.queue.duration`, `keyframe.model.ttft`, `keyframe.model.generation.duration`, `keyframe.model.tokens_per_second`, `keyframe.jobs.queue.duration`, `keyframe.analysis.realtime_factor`, and `keyframe.analytics.writes`; `media_kind="audio"` on the analysis metrics; `analysis:audio` and `job audio` spans.
- Default settings ship local models instead of the mock provider: `ollama-gemma3-4b` (default vision), `ollama-qwen3-vl-8b`, `ollama-gpt-oss-20b` (default text), and `whisper` (default transcription, `Systran/faster-whisper-small`). The Compose stack adds `keyframe-whisper` (speaches 0.8.3 CPU) with a model cache volume and a one-shot model download, and reaches the host's Ollama through `host.docker.internal`.
- `REST_API.md` has a full table of contents, the README an API overview and a segment retrieval walkthrough, `TELEMETRY.md` documents every collected statistic, and the Postman collection has Audio, Segments, and Analytics folders.

- Listening: `POST /v1.0/audio` sends the audio itself to a listening model for Summarize, Extract, and section functions, with the transcript as a hint the model is told to overrule. New request member `Listen` (`ListenSpec`: `Enable`, default true; `Model`; `Rendition`; `SampleClips`, default 4; `ClipSeconds`, default 30) and setting `Inference.DefaultListening`. Listening endpoints are completion endpoints whose provider accepts audio input: Gemini, OpenAI-compatible servers (llama.cpp `llama-server`, vLLM, and OpenAI audio models at `https://api.openai.com/v1`), and the mock provider. Listening is resolved when the job starts, so queued jobs use current endpoint health.
- Listening renditions: the audio sent to a model is its own rendition (`AudioRenditionSpec`: `Format` `Mp3`, `Wav`, or `Flac`; `SampleRate`; `Channels`; `BitrateKbps`), mono mp3 at 16 kHz and 64 kbps unless the request or the `Media.Listen*` settings say otherwise. Long recordings are heard whole when they fit the listen budget and the inline size limit, otherwise as per-section clips or evenly spaced excerpts, with a warning; rendered clips are checked against the endpoint's inline limit and shortened to fit.
- Measurements: `Functions.Measure` (on by default) adds `AudioMeasurements` from one ffmpeg pass (plus a mid/side pass for stereo): integrated loudness, loudness range, true peak, peak and RMS level, crest factor, peak count, `ClippingLikely`, silence ratio, count, and leading and trailing silence, channels, `StereoWidthDb`, and `EffectivelyMono`. No model calls; the figures also go into prompts as data. A request with every other function off is a measure-only job.
- Sections: `Functions.Sections` (off by default) splits a recording at silences found by ffmpeg `silencedetect` (`SectionDetectionSpec`: `SilenceDb`, `MinSilenceMs`, `MinSectionMs`, `MaxSectionMs`, `MaxSections`) and runs per-section Summarize and Extract (purposes `SectionSummarize` and `SectionExtract`). With `TextModel` set, the whole-recording results are reduced from the section results. Responses carry `Sections` (`SectionResult`), and each section can be cut out with `POST /v1.0/segment`.
- Excerpts: recordings longer than the listen budget are heard as `Listen.SampleClips` evenly spaced clips of `Listen.ClipSeconds`, labeled with their offsets, shortened with a warning when they would exceed the budget or the inline limit.
- Scene audio: `Scenes.Audio` (`SceneAudioSpec`: `Enable`, default true; `Rendition`) attaches each scene's audio to that scene's calls when the vision endpoint accepts audio. It never causes a `400`; otherwise scenes run on frames and transcript as before.
- `Listening` (`ListeningInfo`: `Listened`, `Mode`, `Reason`, `Endpoint`, `Model`, `Rendition`, `DurationMs`, `HeardMs`, `Clips` of `ListenClip`) on every audio response and on video responses with scenes, so a consumer can always tell whether the audio was heard. New enums `ListeningModeEnum`, `ListenSkipReasonEnum`, `ListenFormatEnum`, and `ListenClipScopeEnum`; new stages `Measure`, `SectionDetection`, `ListenExtraction`, and `Sections`.
- `POST /v1.0/audio` returns `400` when `Listen.Model` names an endpoint that is missing, inactive, not a completion endpoint, or cannot take audio, when a `Flac` rendition targets an `OpenAiCompatible` endpoint, and when Transcribe is off and listening would fall back.
- `EndpointResponse.SupportsAudioInput` on `GET /v1.0/endpoints`.
- Settings: `Inference.DefaultListening`, `Inference.HealthProbeIntervalMs` (default 300000), `Inference.UnhealthyProbeIntervalMs` (default 15000), `Endpoints[].MaxInlineMediaBytes` (default 20971520), `Endpoints[].MaxListenSeconds` (default null), `Media.ListenFormat`, `Media.ListenSampleRate`, `Media.ListenChannels`, `Media.ListenBitrateKbps`, `Media.MaxListenSeconds` (default 1200), `Media.MeasureSilenceDb`, `Media.MeasureMinSilenceMs`, `Media.ClippingTruePeakDbtp`, `Media.ClippingMinPeaksPerMinute`, and `Media.MonoMaxSideDb`, all applied live.
- Metrics and spans: `keyframe.model.input.audio.bytes` (histogram by provider and purpose) and `keyframe.analysis.listen.total` (counter by media kind, mode, and reason); ffmpeg operations `audio_measure`, `section_detect`, and `listen_extract`; `keyframe.input_audio_clips` and `keyframe.input_audio_bytes` on model call spans. Grafana panels for listening by mode, listening fallbacks by reason, audio bytes sent to models by provider, model calls with audio by purpose, and the new stages and ffmpeg operations.
- Local listening services: the shipped `keyframe.json` files add a `llama-listen` endpoint (Voxtral Mini 3B on a host `llama-server` at port 8720, one concurrent request, a 600000 ms timeout, and a 120-second listen budget) and set it as `DefaultListening`; the Docker files also add an inactive `vllm-voxtral` endpoint. Compose profiles `listen` (`keyframe-llama`, llama-server on CPU, host port 8720) and `listen-gpu` (`keyframe-vllm`, vLLM with Voxtral on an NVIDIA GPU, host port 8730), both bound to loopback, with persistent model directories `docker/llama-models` and `docker/vllm-models` that are git-ignored, docker-ignored, and kept by restarts, updates, and factory resets. The factory samples add `sample.mp3` (three spoken clips from `test-data/audio` separated by silences).
- Dashboard: listening, measurement, and section controls on Analyze Audio, scene audio on Analyze Video, listening results and the section timeline, `SupportsAudioInput` on Endpoints, and the new settings.
- SDKs (C#, JavaScript, Python): the new request, response, and settings members and enums, with harness cases.
- MCP: `keyframe_audio_analyze` takes `Listen`, `Measure`, and `Sections` and tells agents to read `Listening.Listened`; `keyframe_video_analyze` takes `Scenes.Audio`; `keyframe_endpoints_list` reports `SupportsAudioInput`.
- Postman: requests for listening to a track, listening with vLLM, a custom rendition, measure-only, sections of a long recording, and scenes with audio.
- Tests: listening, measurement, section, and scene audio suites, captured ffmpeg measurement output from ffmpeg 6.1 and 9.0, and opt-in live listening cases for Gemini, OpenAI, llama-server, and vLLM (`GEMINI_API_KEY`, `OPENAI_API_KEY` with optional `KEYFRAME_TEST_OPENAI_AUDIO_MODEL`, `KEYFRAME_TEST_LLAMA_URL`, `KEYFRAME_TEST_VLLM_URL`).
- Documentation: listening, measurements, sections, and scene audio in `REST_API.md`, `MCP_API.md`, `README.md` (including the local listening server and hosted listening endpoints), `DOCKERHUB_README.md`, `TELEMETRY.md`, and `TESTING.md` (including how to obtain live provider credentials).

### Changed

- On/off settings are named `Enable` everywhere: `Analytics.Enabled` and `RequestHistory.Enabled` are now `Analytics.Enable` and `RequestHistory.Enable` in the server, the C#, JavaScript, and Python SDKs (`analytics.enable` in Python), the dashboard, the Postman collection, the docs, and the shipped `docker/keyframe.json` and `docker/factory/keyframe.json`. There is no alias: a settings file that still says `Enabled` is ignored for those two members, which then use their default of `true`.
- Health probes run on configurable intervals: `Inference.HealthProbeIntervalMs` (default 300000) for healthy endpoints, replacing the hard-coded five minutes, and `Inference.UnhealthyProbeIntervalMs` (default 15000) for unhealthy or unchecked ones. A model call that gets no HTTP response marks its endpoint unhealthy at once. `EndpointResponse.IsDefault` also covers the default listening endpoint. Endpoints are probed concurrently, the first probe runs within a second of startup, and a scheduled probe skips an endpoint whose concurrency gate is full instead of queuing behind real work, keeping its last state.
- Model containers start before the server: `keyframe-server` declares `depends_on` with `condition: service_healthy` and `required: false` on `ollama`, `keyframe-llama`, and `keyframe-vllm` (Docker Compose 2.20 or later), so a model container in an active profile is healthy first and the first start with a model profile waits for the download. `reset.sh`, `reset.bat`, `update.sh`, and `update.bat` stop every model profile.
- `Listen.Enable` and `Scenes.Audio.Enable` default to true. When no usable audio-capable endpoint is available, audio falls back to transcript-only analysis and video scenes to frames and transcript, flagged in `Listening` (`Listened: false` with a reason code) and, for audio fallbacks that mean something went wrong, a warning.
- The Docker stack listens through llama-server on the host by default (`Inference.DefaultListening` is `llama-listen` in the shipped settings files). A settings file created from scratch has no listening endpoint.
- Measurements run by default on audio (`Functions.Measure.Enable` true). Set it to false for the previous cost profile.
- Summarize, Extract, and section functions accept `Listen` in place of `Transcribe` as their evidence, so instrumental music can be analyzed; the empty-transcript skip applies only when the analysis does not listen. "Enable at least one function" now counts Measure and Sections.
- `InputAudioBytes` on model calls, totals, analytics rows, and `StatBlock` now also counts audio clips attached to completion calls, not only transcription audio. For an audio analysis that listened, the analytics `VisionEndpoint` and `VisionModel` columns hold the listening endpoint and model.
- A listening request to an `OpenAiCompatible` endpoint sends the system prompt at the start of the user message instead of as a separate system message. Voxtral (through vLLM and mistral-common) rejects any request that has both a system prompt and audio; OpenAI and llama-server accept either shape.
- The `listen-gpu` service builds `docker/vllm/Dockerfile`, which adds `mistral-common[audio]` to `vllm/vllm-openai:v0.33.0`; the official image lacks the `soundfile` dependency Voxtral needs. `VLLM_GPU_MEMORY_UTILIZATION` (default 0.85) sets vLLM's share of GPU memory for shared or unified-memory GPUs.
- A named `TextModel` endpoint is checked when the audio request is submitted even when listening is healthy, so a misspelled endpoint is always a `400`.
- The factory `sample.mp3` is three spoken clips from `test-data/audio` separated by silences; the default local listening model, a speech model, invents speech for synthetic tones.
